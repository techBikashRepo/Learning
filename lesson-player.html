Lesson 16

HTTP Status Codes

8 min read +20 XP Intermediate

What You'll Learn

  • Understand the 5 main categories of HTTP status codes
  • Learn the most common status codes and their meanings
  • Know when servers return specific status codes
  • Debug HTTP issues based on status codes

Introduction

When a client (like a web browser) sends an HTTP request to a server, the server processes that request and sends back a response. Every HTTP response includes a status code — a three-digit number that tells the client whether the request was successful, failed, or needs further action.

Understanding status codes is essential for debugging web applications and understanding how the web works.

The 5 Categories

HTTP status codes are divided into 5 categories based on their first digit:

💡
Pro Tip: The first digit tells you the category, the last two digits give more specific information.

1xx — Informational

Rare in practice. Indicates that the request was received and the process is continuing.

  • 100 Continue — Server received request headers, client can send body
  • 101 Switching Protocols — Server is switching to a different protocol

2xx — Success

The request was successfully received, understood, and accepted.

  • 200 OK — Standard success response
  • 201 Created — Resource was successfully created
  • 204 No Content — Success but no content to return
Example Response 
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 48

{
  "message": "User created successfully",
  "id": 12345
}

3xx — Redirection

Further action is needed to complete the request, usually a redirect to another URL.

  • 301 Moved Permanently — Resource permanently moved to new URL
  • 302 Found — Resource temporarily at different URL
  • 304 Not Modified — Cached version is still valid

4xx — Client Error

The request contains bad syntax or cannot be fulfilled. These are mistakes on the client side.

  • 400 Bad Request — Malformed syntax or invalid request
  • 401 Unauthorized — Authentication required
  • 403 Forbidden — Server refuses to fulfill request
  • 404 Not Found — Resource doesn't exist
  • 429 Too Many Requests — Rate limit exceeded
⚠️
Common Confusion: 401 means authentication failed (wrong/missing credentials), while 403 means you're authenticated but don't have permission.

5xx — Server Error

The server failed to fulfill a valid request. These are mistakes on the server side.

  • 500 Internal Server Error — Generic server error
  • 502 Bad Gateway — Invalid response from upstream server
  • 503 Service Unavailable — Server temporarily overloaded or down
  • 504 Gateway Timeout — Upstream server didn't respond in time

Real-World Example

Let's say you're building an e-commerce site. Here's what different status codes might mean:

Scenario: User tries to purchase a product

Code Situation Meaning
200 Order successful ✅ Everything worked
400 Missing credit card number ❌ Client sent incomplete data
401 Not logged in ❌ Authentication required
403 Account suspended ❌ Access denied
404 Product no longer exists ❌ Resource not found
500 Payment processor crashed ❌ Server error

Key Takeaways

  • 2xx = Success — Everything went well
  • 3xx = Redirect — Go somewhere else
  • 4xx = Your fault — Client made a mistake
  • 5xx = Server's fault — Server had a problem
🎯
You're doing great! Understanding status codes will make debugging API issues much easier.
