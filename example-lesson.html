What is a Network?

A network is a collection of interconnected devices that can communicate and share resources with each other. These devices might be computers, smartphones, servers, printers, or any other hardware capable of sending and receiving data.

Understanding networks is fundamental to modern software development. Every time you load a webpage, send an email, or stream a video, you're using a network. For technical interviews, you need to understand not just what networks are, but how they work at a deep level.

The Basic Concept

Think of a network like a postal system. In a postal system:

  • You have senders (people writing letters)
  • You have receivers (people getting letters)
  • You have addresses (locations where letters go)
  • You have infrastructure (post offices, mail trucks, sorting facilities)
  • You have protocols (rules about envelope sizes, postage, zip codes)

Computer networks work the same way, just with data instead of physical letters.

💡

Interview Tip

When explaining networking concepts in interviews, analogies like the postal system help demonstrate your ability to communicate complex ideas simply. Interviewers value clear thinking.

Key Components of a Network

1. Nodes (Devices)

A node is any device connected to a network. This includes:

  • Computers — Desktops, laptops, workstations
  • Servers — Powerful computers that provide services to other devices
  • Mobile devices — Smartphones, tablets
  • IoT devices — Smart TVs, cameras, thermostats
  • Network hardware — Routers, switches, access points

Each node has a unique identifier (like an IP address) so other nodes know where to send data.

2. Links (Connections)

Links are the physical or wireless pathways that connect nodes. They can be:

  • Wired — Ethernet cables, fiber optic cables
  • Wireless — WiFi, Bluetooth, cellular networks

3. Protocols (Rules)

Protocols are standardized rules that define how data is formatted, transmitted, and received. Without protocols, devices couldn't understand each other — like trying to have a conversation where one person speaks English and another speaks Japanese.

Common protocols you'll encounter:

Protocol Purpose Layer
HTTP/HTTPS Web page transfer Application
TCP Reliable data delivery Transport
IP Addressing and routing Network
DNS Domain name lookup Application
⚠️

Common Mistake

Don't confuse the Internet with a network. The Internet is a specific global network that connects millions of smaller networks. A network can exist completely offline (like a local home network).

How Data Travels

When you send data across a network, it doesn't travel as one big chunk. Instead, it's broken into small pieces called packets.

Here's what happens when you visit a website:

1. Your browser creates an HTTP request
2. Request is broken into packets
3. Each packet gets source & destination IP addresses
4. Packets travel through multiple routers
5. Routers determine best path for each packet
6. Destination receives packets
7. Packets are reassembled into original message
8. Server sends response (repeats process in reverse)

This process happens in milliseconds, thousands of times per second during a typical browsing session.

Example: Simple Network

Let's look at a simple home network:

Internet (ISP)
    |
    | (Modem)
    |
[Router/WiFi]
    |
    +--- Laptop (192.168.1.10)
    +--- Phone (192.168.1.11)
    +--- Smart TV (192.168.1.12)
    +--- Desktop (192.168.1.15)

In this setup:

  1. The modem connects your home to your Internet Service Provider (ISP)
  2. The router manages your local network and assigns IP addresses
  3. Each device gets a private IP address on your local network
  4. The router has a public IP address visible to the Internet
ℹ️

Quick Terminology

  • Upstream — Data you send (upload)
  • Downstream — Data you receive (download)
  • Bandwidth — Maximum data transfer rate
  • Latency — Time delay in data transfer

Why Networks Matter for Developers

As a software engineer, you'll work with networks constantly:

  • Web development — Client-server communication via HTTP
  • API design — Building services that communicate over networks
  • Database connections — Querying remote databases
  • Microservices — Services communicating across networks
  • Cloud computing — Everything runs on networked infrastructure
  • Debugging — Network issues are common in production

Understanding networks helps you:

  • Debug connectivity issues
  • Optimize application performance
  • Design secure systems
  • Make informed architectural decisions
  • Ace technical interviews

Key Takeaways

✅

Remember These Points

  • A network is devices connected to share data
  • Networks need nodes, links, and protocols
  • Data travels in packets, not as single messages
  • Every device on a network has an address (IP)
  • Protocols define the rules for communication
  • The Internet is a network of networks
